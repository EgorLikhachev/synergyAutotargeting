# Журнал архитектурных решений (ADR)

Формат унаследован от Autotargeting (docs/sdd/decisions.md).

---

## ADR-001: Rust-first — Python/C++ только по необходимости

- **Статус:** принято (требование заказчика, 2026-09-01)
- **Контекст:** bkb — Python (быстро итерировался, но монолит с дублированием,
  хрупкой синхронизацией через имена потоков); Autotargeting — Rust- workspace
  с 294+ тестами и C++ NPU-мостом.
- **Решение:** весь рантайм — Rust. C++ допустим только как фолбэк NPU-моста;
  Python — только разовые диагностики (v4l2-ctl, rknnlite-пробы).
- **Последствия:** сборка на борту медленнее (кроcс-компиляция не настроена),
  зато один язык, типобезопасность на границах, нет GIL, нет ABI-граблей D-008.

## ADR-002: In-process FFI к NPU вместо сокет-моста

- **Статус:** принято
- **Контекст:** Autotargeting гонял YOLOv8 через C++ rknn-bridge по Unix-сокету
  с base64-кадрами — 96 мс на раунд (D-015), потолок детектора ~10 FPS.
- **Решение:** собственный `crates/rknn-sys`: прямые extern-C байндинги к
  librknnrt.so, zero-copy через rknn_set_io_mem, инференс в потоке детектора.
- **Альтернатива:** тащить rknn-bridge как сабпроцесс — сохраняет 96 мс накладных.
- **Риски:** корректность FFI-структур — снята сверкой с официальным rknn_api.h
  (вендорится в крейте) и портированием логики 1:1 из проверенного rknn_model.cpp.

## ADR-003: NanoTrack на tract + два статических backbone

- **Статус:** принято
- **Контекст:** TrackerNano в OpenCV unavailable из Rust; ONNX Runtime (ort) на
  Debian 12 aarch64 не линкуется (D-008 из Autotargeting).
- **Решение:** tract (чистый Rust). Исходный ONNX backbone экспортирован со
  статическими формами входа 255×255; tract чтит их, OpenCV — игнорировал.
  Поэтому backbone пересохранён в двух статических вариантах: 127×127 (шаблон,
  `nanotrack_backbone_127.onnx`, формы пересчитаны onnx.shape_inference) и
  255×255 (поиск, оригинальный `..._sim.onnx`).
- **Замеры (x86 dev, release):** backbone127 4 мс + backbone255 14 мс + head 3 мс.
- **Фолбэк:** C++ OpenCV TrackerNano-бридж (не понадобился).

## ADR-004: Детектор = RKNN-модель bkb, layout с автоопределением

- **Статус:** принято
- **Контекст:** готовой .rknn под наш класс-набор нет; конвертация yolov8n.onnx
  требует rknn-toolkit2 на x86 Linux. У bkb есть полевые модели rk3588.
- **Решение:** `models/model_5_dynamic_rk3588.rknn` (5 классов — уточняется
  эмпирически, см. HARDWARE_TEST_RESULTS). Декодер сам определяет layout:
  6 выходов → ветки bkb (DFL, без sigmoid), 1 выход → голова Autotargeting
  (sigmoid по D-010). Динамическая форма входа — rknn_set_input_shapes(640).
- **Альтернатива:** конвертация yolov8n COCO на x86 — отложена (нет машины
  с Linux+x86 под рукой ночью).

## ADR-005: Гибрид C — правила слияния детекции и трекинга

- **Статус:** принято
- **Решение:** детекция каждые N кадров (по умолчанию 10) в отдельном потоке
  (NPU не блокирует трекинг). Выбор цели: (приоритет класса, IoU с текущим
  боксом, confidence). Реинициализация трекера на боксе детекции всегда
  (точнее трекера). Потеря: score < min_track_score `lost_patience` кадров
  подряд, либо бокс у края кадра → форс-детекция на следующем кадре.
  Стабилизация центра: скользящее среднее bkb (Stabilizer).
