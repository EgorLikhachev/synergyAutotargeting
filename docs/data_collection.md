# Протокол сбора данных для дообучения детектора (R1)

Дата: 2026-09-09. Цель: накопить датасет дневных мелких целей для
дообучения модели (R1 из refvideo/RESULTS — единственный работающий путь
улучшения дневного канала; тайл-инференс R2 проверен и отклонён, ADR-022).

## Почему это важно

Полнота детекции на дневных целях сейчас 3–8 % (цели 7×4 px, p90 16×16).
Модель таких целей в трейне не видела. Дообучение с аугментацией
«даунскейл цели до 4–16 px» — рекомендация №1 по эффекту. Для него нужен
датасет полевых записей + разметка.

## Как записывать (оператору)

1. Пульт → кнопка **ЗАПИСЬ (R)** — пишет сырой MJPEG (replay-совместимый
   формат борта, без пережатия). Стоп — та же кнопка. Файлы:
   `dist/operator-ui/records/<дата>-<время>.mjpg`.
2. Сцены (главное — разнообразие, а не количество дублей):
   - небо чистое / облачное / с контрастным фоном (кроны, строения);
   - цель — тёмный силуэт 5–30 px (БПЛА/птица/объект на дистанции);
   - движение: статика, медленный проход, быстрый проход, уход за край;
   - разное время суток/освещение.
3. Объём: **20+ роликов по 30–60 с** (пару роликов в день достаточно);
   на ролике цель видна большую часть времени.
4. Не монтировать и не пережимать — сырые файлы как есть.

## Куда складывать

```
C:\dev\synergyAutotargeting\dataset\raw\<ГГГГММДД>_<сцена>.mjpg
```
(например `20260914_небо-быстрыйпроход.mjpg`; каталог в .gitignore).

После складывания прогнать контроль качества (без борта, ~секунда на
ролик): `python tools/dataset_check.py dataset/raw` — проверит
целостность кадров, длительность 30–60 с, разрешение и темноту; резкость
и яркость покажет подсказкой с номером худшего кадра (окончательно
смаз отсекается глазами по этому кадру).

## Обработка (когда наберётся 15–20 роликов)

1. Прогон через replay-стенд: `refvideo/run_replays.sh` (после заливки на
   борт) → метрики «до» для сравнения с «после» дообучения.
2. GT-разметка: `refvideo/gt_extract.py` (полуавтомат: разметка первых
   кадров + трекер; допуск проверять глазами на сложных сценах).
3. Решение о трейн-пайплайне (отдельная задача: аугментации, экспорт
   9-веточной RKNN-модели, валидация replay-стендом — критерий: дет-цель
   на дневном канале ×3+ к базовой линии из RESULTS.md).
