# ROADMAP — от сопровождения к наведению

Обновлён: 2026-09-02. Вводные: **цель системы — наведение**; камера жёстко
на носителе (без гимбла, виброразвязки, демпфера; OV9782 — глобальный
затвор); на рабочей машине есть WSL и Docker; эталонное видео ожидается.

База: гибрид C доказан на железе — 28.7 FPS, 100% сопровождение (демо-цель),
трекинг 30.3 мс (tract, CPU), NPU-детекция 35.8 мс @640, push-стрим 16 FPS.

---

## Фаза A — Полевая валидация детекции ✱ ждёт эталонное видео

Прогон с объектом без `--demo-detect`, калибровка `conf_threshold` под
реальный отклик модели, имена классов в конфиг. Сценарии: захват →
сопровождение → движение → закрытие рукой → повторный захват. Под жёсткий
монтаж: тест с покачиванием камеры — устойчивость трекера к глобальному
смещению кадра. Артефакты: телеметрия, запись стрима,
HARDWARE_TEST_RESULTS §9, закрытие открытых вопросов SDD №1/№3.

**Критерии:** детекции > 0; TRACKING ≥ 90% при объекте в кадре;
повторный захват ≤ 1 с.

## Фаза C — NanoTrack на NPU ✱ критическая, стартует немедленно

Обязательное условие наведения без стабилизации: при 60 FPS бюджет кадра
16.7 мс — трекер обязан уйти с CPU (сейчас 30.3 мс).

1. Стенд конвертации: rknn-toolkit2 в WSL/Docker.
2. Backbone 127/255 + head → RKNN int8; калибровочный набор — снапшоты
   с камеры.
3. Бэкенд трекера за трейтом (`tract` | `rknn`), выбор конфигом, A/B на
   синтетике. Риски: точность int8 (IoU с текущим ≥ 0.8); двухвходовый head
   может не конвертиться → гибрид (backbone на NPU, head на CPU).
4. Режим камеры 60–100 FPS: меньше смаз от вибраций, ниже латентность
   кадр→команда.

**Критерии:** track < 10 мс; пайплайн ≥ 45 FPS; энд-ту-энд латентность
кадр→бокс < 35 мс.

## Фаза D — Коммандер наведения (центральная фаза)

Без гимбла — управление всей платформой (rate-mode), точность ограничена
механикой:

1. Контур: ошибка (цель − центр кадра, px) → PID (скорость поворота) →
   драйвер. Предиктор Лин./Калман (в коде), anti-windup, deadband,
   ограничение slew-rate.
2. Компенсация вибраций: фильтрация ошибки (стабилизатор), короткая
   выдержка камеры, адаптивная частота детекции при резких поворотах.
3. Драйвер исполнителя — интерфейс/протокол уточнить при старте фазы
   (UART/PWM/I2C/CAN).
4. Симулятор платформы (инерция + вибрации) для отладки без железа.

**Критерий:** удержание цели в окне ±30 px на движущейся цели,
перерегулирование < 20%, задержка реакции < 150 мс.

## Фаза E — Деплой и надёжность

systemd + автозапуск + watchdog; кросс-компиляция x86→aarch64 (сборка
2.5 мин → ~30 с); soak 8 ч (RSS, температуры); опционально апгрейд ядра —
может убрать TCP-quirk (только после бэкапа).

**Критерии:** 8 ч без падений; автостарт после снятия питания.

## B+ (впитывается по ходу)

Таймстемп и det-скор на OSD; `--record` запись стрима; H.264 (mpph264enc)
при переходе на Wi-Fi/удалённый доступ.

## Порядок

**C немедленно** (пока ждём видео) → **A** по приходу эталонного видео на
быстрой конфигурации → **D** (нужен ввод по исполнителю) → **E**.

## Бэклог-детали

- **COCO-фолбэк (N3): ОТКЛЮЧЕНО** (ADR-014, 2026-09-03). Путь детекции с
  80-классовой моделью валидирован на борту, но int8 единого выхода
  [1,84,8400] схлопывает cls-логиты (conf=0.5 артефакт). Реактивация:
  9-веточный экспорт yolov8 + layout TwoHead в декодере; код сохранён.
