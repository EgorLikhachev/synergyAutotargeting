# Подключение GEPRC GEP-F405-HD V3 (стек TAKER F405) к ROCK 5A

Дата: 2026-09-04. Статус: подготовлено к сборке, проверка на железе — когда борт вернётся в сеть.

## 1. Идентификация платы

Заказчик назвал плату «gep rc gep-f105-ho v3». Такой модели в каталоге GEPRC нет —
по совпадению ревизии (V3) и маркировке это **GEP-F405-HD V3** — полётник из состава
стеков GEPRC TAKER F405 (BL32 70A / BLS 50A, старшие ревизии). Имя на шелкографии
платы: **`GEP-F405-HD V3 -1.1`**. На плате со стороны компонентов есть маркировка
«GEP-F405-H3…» (обрезано) — это она.

Паспорт платы (со страницы [GEPRC GEP-F405-HD V3](https://geprc.com/product/gep-f405-hd-v3-flight-controller/)):

| Параметр | Значение |
|---|---|
| MCU / IMU | STM32F405RGT6 / ICM-42688-P (SPI) + барометр |
| Питание | 3–6S LiPo (XT60 на ESC стека) |
| BEC | двойной: **5 В / 3 А** и **12 В / 2,5 А** |
| UART | **6 × UART**, выведены на пады |
| OSD | AT7456E, Blackbox 16 МБ |
| Разъёмы | DJI Air Unit/O3 (6-pin, верх), USB-C, моторные 8-pin M1–M6 |
| Таргет Betaflight | **GEPRCF405** |
| Логика UART | 3,3 В — совместима с ROCK 5A напрямую |

Фото платы: [вид сверху (пады)](https://geprc.com/wp-content/uploads/2023/11/2_DeMain_0000-5.jpg),
[вид снизу](https://geprc.com/wp-content/uploads/2023/11/5_DeMain_0000-5.jpg),
[обзор Oscar Liang стека TAKER F405](https://oscarliang.com/geprc-taker-f405/).

## 2. Что соединяем

Задача: полётник принимает RC-каналы по **MSP over UART** (протокол `SET_RAW_RC`,
115200 8N1, 30 Гц, 16 каналов) — это шлёт наш крейт `commander` (наследие bkb,
ADR-013). Итого **3 провода**: TX→RX (кроссом), RX←TX, общий GND. Питание НЕ
соединяется — у каждой платы своё.

```
 ┌─ GEPRC GEP-F405-HD V3 ─┐              ┌─ ROCK 5A (40-pin) ──────┐
 │                         │              │                          │
 │  T1 (TX1) ──────────────┼──────────────┼─ pin 33  UART7_RX_M2     │
 │  R1 (RX1) ──────────────┼──────────────┼─ pin 22  UART7_TX_M2     │
 │  G ─────────────────────┼──────────────┼─ pin 6/9/14/... GND      │
 │                         │              │                          │
 │  B+/B- ← XT60 ← АКБ 3-6S│              │  USB-C PD ← свой БП      │
 └─────────────────────────┘              └──────────────────────────┘
```

## 3. Сторона FC: пады GEP-F405-HD V3

Расположение подтверждено по фотографиям GEPRC (плата сверху, USB-C снизу,
DJI-разъём сверху):

| Группа палов | Где на плате | Назначение |
|---|---|---|
| `G / 5V / R2 / T2` | левая грань, средний ряд | **UART2** (RX2=R2, TX2=T2) |
| `G / R1 / T1` | левая грань, нижний ряд | **UART1** (RX1=R1, TX1=T1) |
| `R4 / T4` (+G) | правая грань | **UART4** |
| `R3/T3`, `R5/T5`, `R6/T6` | найти по шелкографии (см. ниже) | UART3/5/6 |
| `G 12V T? R? 5V G` | верх, разъём DJI 6-pin | UART DJI (обычно UART1) + питание O3 |
| `B+ / B-` | рядом с XT60-входом стека | вход батареи (на FC — через стек) |
| `M1…M6` | нижняя грань и правая (M5/M6) | моторные 8-pin разъёмы к ESC |
| `CAM / G / 5V` | нижняя грань | аналоговая камера (не используем) |
| `LED`, `BZ+/BZ-`, `SDA/SCL` | по шелкографии | периферия (не используем) |

**Рекомендация: UART1 (пады `T1`/`R1`)** — подтверждённое расположение на левом
краю, подальше от силовых цепей; UART1 в Betaflight по умолчанию свободен от
SBUS-инверсии и не занят DJI-разъёмом.

Точные места палов R3/T3, R5/T5, R6/T6 с фотографий не читаются — на плате они
подписаны так же (`R<n>` = RX, `T<n>` = TX). Если решите использовать другой UART —
ищите пару `R<n> T<n>` на шелкографии; любой из шести подходит, меняется только
настройка порта в Betaflight.

> Не путать: `R`/`T` на шелкографии GEPRC = **RX/TX** этого UART, а не «receiver pad».

## 4. Сторона ROCK 5A: 40-pin гребёнка

Из [Radxa Wiki ROCK 5A GPIO](https://wiki.radxa.com/Rock5/hardware/5a/gpio).
Нумерация пинов стандартная Raspberry-совместимая (1 — квадратный у края).

| UART | device | Ревизия X1.1 | Ревизия X1.2 | Примечание |
|---|---|---|---|---|
| **UART7** | `/dev/ttyS7` | TX=**22**, RX=**33** | TX=**22**, RX=**33** | ✅ одинаково в обеих ревизиях — **рекомендуем** |
| UART6 | `/dev/ttyS6` | TX=**5**, RX=**3** | TX=**19**, RX=**21** | пины меняются между ревизиями! |
| UART4 | `/dev/ttyS4` | TX=7, RX=29 | TX=7, RX=29 | занят потенциально SPI/I2C-планами |
| UART2 | `/dev/ttyS2` | TX=8, RX=10 | TX=8, RX=10 | ❌ debug-консоль — не занимать |
| UART8 | `/dev/ttyS8` | TX=32, RX=40 | TX=32, RX=40 | занят под CSI-экраны/UART-периферию Radxa |

GND на гребёнке: пины **6, 9, 14, 20, 25, 30, 34, 39**.

Ревизию своей платы смотреть на шелкографии (X1.1 / X1.2) или:
`cat /proc/device-tree/model`. Т.к. UART7 одинаков в обеих ревизиях — используем
его и меняем `device` в конфиге с `ttyS6` (там был выбор по умолчанию) на `ttyS7`.

Уровни: GPIO ROCK 5A = 3,3 В, палы FC = 3,3 В TTL. Согласование не нужно.

## 5. Таблица соединений

| # | FC GEP-F405-HD V3 | ROCK 5A 40-pin | Провод |
|---|---|---|---|
| 1 | `T1` (TX1) | pin **33** (UART7_RX) | сигнальный, любая длина до ~30 см |
| 2 | `R1` (RX1) | pin **22** (UART7_TX) | сигнальный |
| 3 | `G` (рядом с R1/T1) | pin **6** (GND) | земля, не длиннее сигнальных |

Кросс TX→RX обязателен (передатчик к приёмнику с обеих сторон). Полярность не
перепутать критично: постоянная подача 3,3 В на RX с обеих сторон безопасна, но
связи не будет — проверяется осциллографом/логическим анализатором или просто
перекрёстной перестановкой двух проводов.

## 6. Питание

- **Стенд (первые тесты):** FC питается от **USB-C** (питается MCU и UART —
  достаточно), моторные разъёмы к ESC **можно вообще не подключать**. ROCK 5A — от
  своего штатного USB-C PD-БП (≥30 Вт). Аккумулятор НЕ нужен.
- **Полёвка:** FC/ESC от АКБ 3–6S через XT60 (B+/B-). ROCK 5A — только свой БП или
  PD-банк; **запрещено** питать ROCK 5A от BEC 5 В платы (RK3588S берёт пики >3 А
  и требует PD-квитирование) и запрещено подавать 5 В/12 В BEC на гребёнку.
- Соединять земли обязательно (провод №3) — это опорный уровень UART.

## 7. Настройка Betaflight (FC)

Прошивка: Betaflight ≥ 4.4, таргет **GEPRCF405** (выбирается автоматически при
прошивке через [Betaflight Configurator](https://betaflight.com/docs/development/configurator),
плата определяется как GEP-F405-HD V3).

1. **Ports**: UART1 → включить **MSP** (baud 115200 — дефолт MSP, менять не надо).
   Остальные функции порта (Serial RX и пр.) на UART1 выключить.
2. **Configuration → Receiver**: Provider = **MSP RX input** (в CLI — `feature RX_MSP`),
   Channel map = **AETR1234** (наш commander шлёт 16 каналов: 1=roll, 2=pitch,
   3=throttle, 4=yaw, далее aux).
3. **Failsafe** (обязателен — это второй контур безопасности после нашего
   LOST-центрирования): RX loss → `Drop` (или `Land` по выбору), задержка
   минимальная. При пропадании MSP-кадров >0,5 с Betaflight сам уйдёт в failsafe.
4. **Моторы**: до конца настройки — моторные разъёмы отключены. ARM-канал (aux)
   назначить по схеме заказчика; наш `stop` центрует все каналы → throttle=1000,
   arm-канал в off → моторы стоп.
5. Проверка: Configurator → вкладка Receiver — при включённом АРМ в UI оператора
   полоски каналов должны двигаться.

## 8. Включение UART7 на ROCK 5A

На Radxa OS (Debian, ядро 6.1.84) порт появляется после overlay:

```bash
sudo rsetup        # → Overlays → Manage overlays → включить "uart7-m2" → Yes → reboot
ls /dev/ttyS7      # должен появиться
dmesg | grep -i uart
```

Если пункта в rsetup нет — overlay-файл лежит в `/boot/dtbo/` (имя вида
`uart7-m2.dtbo`), подключается через `/boot/extlinux/extlinux.conf`
(`overlays=uart7-m2`). Проверить на месте: `ls /boot/dtbo | grep -i uart`.
Overlay `uart7-m2` — именно M2: пины 22/33.

## 9. config.toml на борту

`~radxa/synergy/config.toml` (в репо — `config.example.toml`):

```toml
[commander]
enabled  = true          # добавить, если нет
device   = "/dev/ttyS7"  # было ttyS6 — сменили на UART7 (пины 22/33)
baud     = 115200
rate_hz  = 30
kp       = 2.0
deadband_px = 6.0
```

Перезапуск: `sudo systemctl restart synergy`.

## 10. Первое включение — чеклист

1. ✅ Моторные разъёмы ESC отключены (или пропеллеры сняты).
2. ✅ Пайка: T1→33, R1→22, G→6. Прозвонка мультиметром: KZ нет, T1 не коротит с R1.
3. ✅ FC прошит, Betaflight настроен (раздел 7), Receiver-вкладка открыта по USB.
4. ✅ ROCK 5A: overlay uart7-m2 включён, `/dev/ttyS7` существует.
5. ✅ `config.toml` [commander] поправлен, сервис перезапущен, лог: `journalctl -u synergy -f`
   — commander должен писать «connected»/«writing frames» без ошибок.
6. ✅ Тест каналов: UI оператора → АРМ ВКЛ → полоски в Receiver-вкладке двигаются
   (roll/pitch реагируют на положение цели). СТОП → все каналы в центр, throttle=1000.
7. ✅ Тест failsafe: закрыть UI при АРМ → через ~1 с борт сам шлёт центры
   (наш барьер), при полном пропадании MSP сработает Betaflight-failsafe.
8. ⬜ Только после п.1–7: подключить моторы (без пропов!), проверить реакцию
   roll/pitch-выходов, затем пропеллеры.

## 11. Безопасность (связь с docs/safety_compliance.md)

- Двухпроводная схема MSP сохраняет два независимых барьера: наш авто-СТОП при
  обрыве control-канала (барьер B5) + failsafe Betaflight по молчанию MSP.
  Рекомендация R2 (RC-failsafe_FC) из аудита закрывается этим подключением.
- Категория останова по ГОСТ Р ИСО 13850: наш СТОП = категория 2 (рабочий
  останов). Аварийный останов пилота дрона — аппаратный выключатель/ARM-канал
  пульта, вне этой схемы.
- Общий провод GND — первый при подключении, последний при отключении.
- Не прошивать FC и не менять wiring при подключённой батарее.
