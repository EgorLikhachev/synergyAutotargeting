# Подключение FC (GEPRC TAKER F405 BLS 60A V2) к ROCK 5A — MSP over UART

Дата: 2026-09-08 (актуализация по итогам сессии отладки связи).
Статус: **электрика и ПО готовы и доказаны; ждём идентификации точек
подключения на стороне FC** (подписи падов — см. §7).

## 1. Идентификация железа

Стек заказчика: **GEPRC TAKER F405 BLS 60A V2 STACK** (маркировка с коробки;
страница: geprc.com/product/geprc-taker-f405-bls-60a-v2-stack/). Полётник
в его составе — **GEP-F405-HD V3** (шелкография `GEP-F405-HD V3 -1.1`).
Прошивка: **Betaflight 4.4.3**, таргет **GEPRCF405** (CLI `version`:
`manufacturer_id: GEPR, board_name: GEPRCF405`).

Паспорт FC: STM32F405RGT6, ICM-42688-P, OSD AT7456E, Blackbox 16 МБ,
**6 × UART** + VCP, логика UART **3,3 В** — совместима с ROCK 5A напрямую.

Карта UART из живого resource-дампа этой платы (CLI `resource`):

| UART | MSP id | TX (пин MCU) | RX (пин MCU) |
|---|---|---|---|
| UART1 | 0 | B06 | B07 |
| UART2 | 1 | A02 | A03 |
| UART3 | 2 | C10 | C11 |
| UART4 | 3 | A00 | A01 |
| UART5 | 4 | C12 | D02 |
| UART6 | 5 | C06 | C07 |
| VCP (USB) | 20 | — | — |

Пады на плате подписаны парами `T<n>`/`R<n>` (= TX/RX UARTn). Расположение
T1/R1 — левая грань (по фото GEPRC); точное расположение остальных пар —
по шелкографии платы.

## 2. Схема соединения

FC принимает RC-каналы по **MSP over UART** (`SET_RAW_RC`, 115200 8N1,
30 Гц, 16 каналов) — шлёт крейт `commander` (ADR-012). Три провода, кросс:

```
 ┌─ GEP-F405-HD V3 ───────┐              ┌─ ROCK 5A (40-pin) ──────┐
 │  T<n> (TX) ─────────────┼──────────────┼─ pin 33  UART7_RX        │
 │  R<n> (RX) ─────────────┼──────────────┼─ pin 22  UART7_TX        │
 │  G ─────────────────────┼──────────────┼─ pin 6   GND             │
 └─────────────────────────┘              └──────────────────────────┘
```

| # | FC | ROCK 5A | Примечание |
|---|---|---|---|
| 1 | `T<n>` (TX) | pin **33** | кросс обязателен |
| 2 | `R<n>` (RX) | pin **22** | кросс обязателен |
| 3 | `G` | pin **6** | общий GND — обязательный, НЕ на 5V/4V5! |

Питание плат не соединяется (у каждой своё; запрещено питать ROCK 5A от
BEC 5 В платы — пики >3 А, требуется PD-квитирование).

**Стенд:** FC от USB-C (MCU+UART хватает), моторные разъёмы ESC отключены;
ROCK 5A от своего PD-БП ≥30 Вт. **Полёвка:** FC/ESC от АКБ 3–6S XT60.

## 3. Настройка Betaflight — ГЛАВНОЕ ОГРАНИЧЕНИЕ

> **Открытие сессии 2026-09-07..08 (корневая причина «настройка не
> сохраняется»):** Betaflight 4.4 при **каждой загрузке** проверяет
> serial-конфиг функцией `isSerialConfigValid()` (вызов из
> `validateAndFixConfig()`, src/main/config/config.c). Правила:
> - MSP-портов не больше **`MAX_MSP_PORT_COUNT = 3`** (msp_serial.h),
>   **VCP считается** и **обязан иметь MSP**;
> - MSP на порту делится только с telemetry/blackbox/VTX_MSP.
> Невалидный конфиг **молча сбрасывается в дефолт — только группа
> serialConfig** (фичи, имя и остальное сохраняются!). Поэтому «MSP на всех
> UART» не выживает перезагрузку, EEPROM при этом пишется корректно.

**Валидный конфиг: MSP максимум на VCP + 2 UART.** Для установки:

- **Автоматически (рекомендуется):** `python tools/fc_setports.py COM4` —
  применяет MSP на VCP+UART4+UART5, проверяет ack на запись/EEPROM и
  **контрольно читает конфиг после перезагрузки** (до 4 попыток).
  Configurator при этом должен быть отключен (держит порт).
- **Поиск нужного UART:** `python tools/fc_finduart.py COM4` — перебирает
  пары {0,1}/{2,3}/{4,5}: применяет валидный конфиг, ребут, проба
  MSP_STATUS с борта (ssh). Пара с ответом `$M>` = подключённый UART.
- **Вручную в CLI:** `serial <id> 1 115200 57600 0 115200` для двух UART +
  вручную набранный `save`. Вставка блока целиком **опасна** — известный
  баг Configurator [#5127]: при пасте последняя строка `save` теряет первый
  символ («ave») и всё выглядит применившимся. Набирай `save` руками.

Приёмник: `feature RX_MSP` (синтаксис 4.4; в 4.5+ это `set rx_provider =
MSP`). Проверено: фича сохраняется и переживает перезагрузки.

Failsafe (второй контур после нашего LOST-центрирования): RX loss → Drop,
задержка минимальная — при молчании MSP >0,5 с Betaflight уйдёт в failsafe.
Channel map AETR1234 (commander: ch1=roll, ch2=pitch, ch3=throttle,
ch4=yaw/arm-aux, далее aux).

## 4. Включение UART7 на ROCK 5A (Armbian)

Борт: **Armbian 26.8.3 trixie vendor 6.1.115** (192.168.0.225). Overlay:

```bash
# /boot/armbianEnv.txt:
overlays=rk3588-uart7-m2
```

(имя с префиксом `rk3588-` — так выбирает fallback-ветка boot.cmd Armbian).
Затем `sudo reboot`, проверить `ls /dev/ttyS7`.

> ⚠️ На Armbian НЕ править `/boot/extlinux/extlinux.conf` — правка overlays
> там убила загрузку Radxa Debian (инцидент 2026-09-05, потребовала
> перепрошивки). Только armbianEnv.txt.

| `fc_txtest.py COM4` | ПК+борт | обратный путь FC→борт: телеметрия LTM/MAVLink на UART, слушаем ttyS7; изоляция найденного порта, финальный MSP-конфиг |
| `msp_probe_board.sh` | борт | MSP_STATUS в ttyS7, ждёт `$M>` (сам стоп/старт synergy) |
| `listen_board.sh [сек]` | борт | сколько байт пришло в ttyS7 + hex-дамп |
| `far_loop.sh` | борт | дальнее эхо: маркеры SYN### через скрутку проводов на дальнем конце |

**Вывод:** борт, пины 22/33, кабель — доказаны; FC программно готов.
Значит, текущие точки пайки на плате FC — **не RX/TX ни одного UART**
(или холодная пайка именно там, или земля не на G). Ранние тесты на пада́х
T1/R1 (обе ориентации) проводились ДО починки персистентности конфига и
ничего не доказывают.

## 7. Открытый вопрос (единственный)

Подписи у точек подключения на FC: заказчик должен прочитать шелкографию
у мест пайки (ожидаем пары вида `T<n>`/`R<n>` + `G`). По подписям —
перенос пайки на настоящую пару UART (любую, меняется только `serial` в
конфиге) → `fc_finduart.py` подтверждает связь за один прогон → тест
каналов при ARM (вкладка Receiver: центры 1500, ch3=1310, ch4=1950).

Альтернатива, если пады нечитаемы: штатный 4-pin разъём приёмника
(подпись RX на нижнем крае FC, пины подписаны `5V RX TX G`) — но в
комплекте стека кабеля SH1.0 нет, нужен отдельный.

## 8. config.toml на борту

```toml
[commander]
enabled  = true
device   = "/dev/ttyS7"   # UART7, пины 22/33 (overlay rk3588-uart7-m2)
baud     = 115200
rate_hz  = 30
# kp=1.8 kd=0.12 lead_s=0.15 — предтюнинг свипом (examples/tune.rs)
```

## 9. Чеклист первого включения

1. ✅ Моторы ESC отключены (или пропеллеры сняты).
2. ✅ Пайка: `T<n>`→33, `R<n>`→22, `G`→6; прозвонка: KZ нет, сигнальные не коротят.
3. ✅ FC: прошит, `feature RX_MSP`, MSP на VCP+выбранный UART
   (`fc_setports.py`/`fc_finduart.py`), failsafe настроен.
4. ✅ Борт: overlay включён, `/dev/ttyS7` есть, [commander] в конфиге.
5. ✅ `fc_finduart.py`/`msp_probe_board.sh` → ответ `$M>`.
6. ✅ Тест каналов: АРМ в UI → вкладка Receiver двигается (центры 1500,
   ch3=1310, ch4=1950); СТОП → центры.
7. ✅ Failsafe: закрыть UI при АРМ → авто-СТОП <1 с (наш барьер B5);
   при полном пропадании MSP — failsafe Betaflight.
8. ⬜ Только после 1–7: моторы без пропов → реакция roll/pitch → пропы.

## 10. Безопасность (docs/safety_compliance.md)

- Два независимых барьера: наш авто-СТОП при обрыве control-канала +
  failsafe Betaflight по молчанию MSP.
- **Запрет заказчика: НИКОГДА не отправлять disarm** (летающая платформа,
  disarm в воздухе = падение) — msp::set_arming() только ручной API.
- Наш СТОП = категория 2 по ГОСТ Р ИСО 13850; аварийный останов пилота —
  аппаратный, вне этой схемы.
- GND подключаем первым, отключаем последним. Не прошивать FC и не менять
  wiring при подключённой батарее.
