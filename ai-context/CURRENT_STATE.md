## FC-интеграция (2026-09-08: УПРАВЛЕНИЕ РАБОТАЕТ)
- **Контур наведения жив end-to-end на стенде**: FC подключён к USB-A
  борта (VCP, udev `/dev/tty-fc` 0483:5740), commander шлёт SET_RAW_RC
  38 Б ~23-30 Гц (throttle 1310 / arm 1950 — доказано strace), FC применяет
  кадры (доказано прямым чтением MSP_RC с борта). Настройка FC не нужна
  вовсе: VCP имеет MSP из коробки + `feature RX_MSP` уже включён.
- **Корневая причина «serial не сохраняется»** (закрыта): BF 4.4
  validateAndFixConfig при каждой загрузке сбрасывает ТОЛЬКО serialConfig,
  если isSerialConfigValid не проходит: MAX_MSP_PORT_COUNT=3 (VCP считается
  и обязан иметь MSP). Валид = MSP на VCP+2 UART.
- UART-провода (полевая задача №2): борт/пины 22/33/кабель доказаны
  (дальнее эхо 29/30), все 6 UART FC проверены в обе стороны (молчание) —
  точки пайки на падах FC не на UART (подписи так и не подтверждены).
  План возврата: мультиметр-прозвонка трёх трасс + serialpassthrough-скан.
- Борт: **DHCP, сейчас 192.168.0.224** (MAC — в приватных заметках; заказчику
  рекомендована статическая аренда на роутере). Паттерн деградации сети:
  TCP умирает при живом пинге (~2 раза/день) — лечится ребутом борта;
  connect_timeout-фикс ускоряет переподключение пушей до секунд.

## Грабли (не повторять)
- **Тесты с блокирующим recv/send без таймаута вешают CI навсегда**:
  sdnotify-тест ждал немедленный WATCHDOG=1, а kick() рейт-лимитирован
  (max(WatchdogSec/2, 250 мс)) — второй recv_from висел вечно; на
  Windows теста нет (cfg unix), поэтому локально было зелёно, а CI-раннер
  умирал по 6-часовому таймауту на каждом пуше (найдено 2026-09-11
  воспроизведением в WSL + strace). Правило: в тестах сокетов всегда
  set_read_timeout; поведение kick/interval — проверять по исходнику.
- **x86-бенчмарки недостоверны для aarch64-решений даже качественно**:
  демозаик «построчный» на x86 +7%, на A76 −130% (ADR-024). Любая
  перф-правка горячего пути — замер на борту до commit'а в main.
- **«Мёртвый» код на Windows может быть живым на Linux**: вызовы под
  cfg(target_os="linux") компилятор хоста не видит — удаление «unused»
  ломает боевую сборку (rgb24_to_nv12, 2026-09-10). Перед удалением
  грепать вызовы с учётом cfg-гейтов; верифицировать
  cargo check --target aarch64 (локально невозможен без кросс-gcc —
  авторитет = CI cross-джоба; WSL на текущем хосте ПУСТ, bash нет).
- **Bash-heredoc c Python-заменами ломается на x-последовательностях**
  (двойной бэкслеш в heredoc = литеральный бэкслеш, паттерн не матчится)
  — правки байт-литералов и строк с экранированием делать инструментом
  Edit, не python-вставками.
- **Keenetic-шлюз не отвечает на unprivileged ping**: у /usr/bin/ping нет
  suid/caps → из user-контекста ICMP идёт dgram-сокетом, шлюз молчит (root/
  raw — отвечает). ICMP-зонды из user-скриптов дают вечный gw=0 — сетевая
  проба только TCP (443/80 шлюза, см. soak.sh) или из root (netwatch).
  Выявлено 2026-09-09 по расхождению soak (gw=0) и netwatch (ping=1).
- **BF 4.4: не ставить MSP больше чем на VCP+2 UART** — молчаливый сброс
  serialConfig при каждой загрузке (выглядит как «не сохраняется»).
- **CLI Configurator: вставка блока ломает хвостовой `save`** (баг #5127,
  «ave» вместо save) — набирать save руками, проверять `serial` до и после.
- **Armbian: overlays только через /boot/armbianEnv.txt** — правка
  extlinux.conf убила загрузку (перепрошивка!).
- UART-порты FC открываются ТОЛЬКО при загрузке: runtime-изменение
  serialConfig невидимо до ребута (не «оживляй» конфиг без перезагрузки).
- Тесты UART на борте: писать в порт паттерном `printf > /dev/ttyS7` в
  фоне + `cat` — вариант с exec-fd и фоновым писателем молча не передаёт.
- librknnrt 2.3.0: NHWC у float-входов, fp16 неточен, opt=3 портит
  fusion, zero-copy → SIGSEGV (ADR-006/011).
- Входящие TCP к user-портам при активном NPU могут не проходить (ADR-009);
  ARP-ответ ≠ живой sshd.
- UVC пере-enumeration меняет /dev/videoN — только udev-алиасы.
- Windows: `ssh -f` умирает; git pull на борту сломан — доставка deploy.sh.
- **Клон File::try_clone ДЕЛИТ указатель позиции с оригиналом** (DuplicateHandle
  → тот же file object; на Unix dup() делит offset так же): seek по клону
  молча сдвигал позицию BufWriter'а, и писатель AVI перезаписывал файл с
  начала после каждого патча заголовка. Патчить «открытый» файл — через
  BufWriter::get_mut() (flush → seek → write → seek End(0)), один дескриптор.
  Найдено 2026-09-13 побитовой сверкой структуры записи.
- **VLC scene-dump непригоден для подсчёта кадров**: фильтр пишет PNG в
  реальном времени воспроизведения и под нагрузкой роняет кадры (183 → 123
  на незанятой машине — при тяжёлых кадрах). Авторитетный счётчик — cv2
  VideoCapture (детерминированный) + байтовая сверка структуры.

## Трекер: ADR-027 — рамка больше не растёт скорингом (2026-09-14)

- Корень полевого симптома «рамка постоянно растёт»: scale-penalty делил
  на size_cal(target_pos) — баг OpenCV-порта (позиция вместо размера) —
  штраф поощрял крупные предсказания, EMA раздувала бокс до краёв кадра.
  Фикс (ветка слита в main, d6eda8b): канонический делитель
  size_cal(target_sz) + защитный кламп ±(20%+3px)/кадр.
- Верификация: mock-тесты (на старой формуле рамка убегает в 640 px, на
  новой стоит), 76 тестов воркспейса, clippy 0, кросс-сборка aarch64+npu.
  Replay до/после — R5 в refvideo/RESULTS.md: day_132749 трек-цель
  19→42 кадра (оф% 90→77), тепловой 414→518, day_133657 −7% (цена
  симметричного штрафа).
- Остаточное (не арифметика, а модель): эпизоды перецепления на крупный
  объект рядом (рука вместо пальца) при score 0.97–0.99 на целях 4–30 px
  — корневой путь R1 (дообучение). Живой тест оператора 2026-09-14
  (запись проанализирована refvideo/cmp_r5/avi_box.py): медиана w 168 px,
  эпизод до 409 px с возвратом, runaway к краям отсутствует.
- Деплой на борту: d6eda8b (md5 207b30e3), synergy.service активен,
  пульт dist = последней сборке.
